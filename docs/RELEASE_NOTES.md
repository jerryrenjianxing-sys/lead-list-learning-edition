# Media Deep Researcher 0.5.3 预览版

- matt 双轴审查后的修复：异常目标重放上限、定时续接认证检查、运行中指定重试时间保留。
- 100条判定只统计内容、评论及回复，账号资料不参与；接口另给出判定记录量。
- 首次执行的关键词优先于已运行任务的再次重试，避免新加入关键词被旧任务占住。
- 调度和任务卡共享同一阻塞判断；认证未确认时显示等待登录或验证。
- 提前成功的访问复查在定时到期后仍经过原生重放登记。
- 已排队的访问复查不会在到期边界被重复延后；共用检查由最早满足条件的关键词触发，仍遵守平台冷却、人工处理和各任务自己的截止时间。
- 账号或环境代次变化后先结束旧环境的待执行检查，避免其长期显示排队并阻挡账号管理或更新准备。
- Windows临时进程作用域显式终止所属树后关闭内核句柄；本机自检使用随包完整Chromium，保留原1.8秒清理检查。新增真实内核引用留存及作用域隔离回归。
- 延续schema 6和冻结的依赖。按2026-10-23新增交付要求，验收后发布安装包并备份升级本机0.5.2；保留所有旧版及原有安装包。审查见review-0.5.3.md，发行验证见validation-0.5.3.md及发行附件。

## 0.5.0 状态与恢复需求（由 0.5.1 一并交付）

状态与恢复升级：任务停止后禁用自动续接，按运行轮次保留范围、结构化证据、增量计数及分页时间线。检查登录、打开平台和保存操作有独立编号；Skill 新增 explain、probe、operation，首页仍只复制 MD。

七平台共用观测与状态结构；新自动探测和冷却仅对抖音启用。搜索使用“美食”作对照，其他动作使用最近成功来源；空页、403、超时或对照失败都不能单独确诊风控。明确限制及疑似限制分别记录，默认一小时后复查，失败再等两小时、四小时，三次后转人工。账号变化、用户停止、相关能力未恢复时不会自动继续。对照正常但原目标持续异常时，仅自动重放一次。

数据库迁移至 schema 5，迁移前备份。SQLite 是业务保存依据，原始文件失败可单独重建。旧客户端及 API v1 保留兼容，采集依赖、上游提交和浏览器版本冻结。
