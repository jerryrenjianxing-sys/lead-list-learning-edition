# 数据、升级与恢复

默认数据位置为 `%LOCALAPPDATA%\MediaWorkbench\data`。程序安装目录和用户数据分离；Velopack 仅替换程序目录。卸载没有删除这个独立数据目录的自定义步骤。环境变量 `MEDIAWORKBENCH_DATA_DIR` 可用于独立测试实例。

## 备份

设置页可备份 SQLite；更新前也会生成 `data/backups/workbench-*.sqlite3`。这份数据库备份包含任务、记录、分析、回执和成果索引。原始文件、成果附件及浏览器会话仍在相邻目录，完整迁移时应在退出软件后复制整个 `data` 目录。

## 恢复数据库

1. 从托盘选择「退出并保存进度」，等待软件退出。必要时查看 `logs/host.log`，确认后台已停止。
2. 复制整个数据目录到另一位置保存现状。不要在后台运行时替换数据库。
3. 将当前 `workbench.sqlite3`、存在的 `workbench.sqlite3-wal`、`workbench.sqlite3-shm` 移入备份文件夹，再把所选备份复制为 `workbench.sqlite3`。
4. 保留 `artifacts`、`runs` 等文件目录。用兼容该备份版本的软件启动，检查任务、记录数与附件。

新版本数据库会拒绝由不兼容的旧版打开。0.1.1 使用结构版本 4，版本 1–3 在迁移前自动备份；新增会话元数据，凭据仍留在本机加密文件与专用浏览器档案。升级失败时可重新运行上一版本完整安装包，再按上述步骤恢复其升级前备份；这一路径仍需在干净系统上做正式回滚验收。

## 接续任务

- 网页或 Agent 关闭：已提交的采集继续；分析等待 Agent 补交下一批。
- 明确退出或后台崩溃：已落库的数据保留，未完成采集标为中断，由用户或 Agent 选择恢复。
- 采集恢复：重新请求并按平台/类型/原生编号去重，可能重复访问远端页面；并非七个平台都能精确接续远端游标。
- 分析恢复：查询固定输入快照中的 pending/failed 范围，用新批次编号补交。重试同一批次或同一写请求时复用原编号。
- 登录失效：在平台登录页完成验证，同账号保存成功后自动续接因认证暂停的任务；账号无法核对时先确认，主动停止的任务不自动继续。
- 登录保存失败：点击“更多操作 → 重试保存”。网络异常保留账号，网络恢复后重试任务，不必重新扫码。凭据不通过接口返回。
- 忘记账号：在平台登录页确认后删除该平台本机档案、恢复档案及加密快照；活动任务期间禁止删除。清理任务记录继续保留账号。
- 跨 Windows 用户或电脑搬迁：数据可以迁移，但 DPAPI 快照通常不可解密，浏览器档案也可能需要重新登录；不承诺账号跨电脑无感迁移。

原始旧项目和基线备份保留在新仓库的相邻目录。新版不会把原来的个人数据、Cookie 或登录状态打进安装包。
