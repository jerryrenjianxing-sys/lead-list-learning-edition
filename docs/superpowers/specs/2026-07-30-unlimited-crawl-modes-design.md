# 三种采集模式与平台返回驱动全量采集设计

## 目标

在现有 Apple 风格 WebUI 中恢复“关键词搜索、指定作品、指定创作者”三种采集模式，并取消项目自身对作品、一级评论、二级回复和账号资料数量的人为限制。

“全量”定义为：持续请求到平台明确返回无下一页、空结果或重复页面；不承诺取得平台未公开、未返回或因权限不可见的数据。

## 界面

- 在展开侧栏增加紧凑的“采集方式”分组，保持首页搜索式布局不变。
- 关键词搜索：
  - 支持多个关键词；
  - 中文、英文逗号均可分隔；
  - 回车只生成标签，手动点击开始才运行；
  - 支持现有多平台登录检查与顺序队列。
- 指定作品：
  - 输入多个作品链接或 ID，回车生成标签；
  - 只允许选择一个平台，避免跨平台误用 ID；
  - 逐项采集作品及其全部公开评论、回复和账号资料。
- 指定创作者：
  - 输入多个创作者主页链接或 ID，回车生成标签；
  - 只允许选择一个平台；
  - 采集创作者公开作品，再采集每条作品的全部公开评论、回复和账号资料。
- 三种模式都保留二维码登录、终端、停止、恢复和数据管理能力。

## 全量规则

- `max_notes_count = 0` 表示不限制作品数。
- `max_comments_count = 0` 表示不限制每条作品的一级评论数。
- `lead_max_accounts = 0` 表示不限制账号资料补采人数。
- 二级回复不设项目数量上限，跟随平台分页直到结束。
- 作品发布者、一级评论者、二级回复者都登记为账号资料候选。
- 账号按“平台 + 平台内部账号 ID”去重，同一账号只补采一次公开资料。
- 不用 10 万等大数字模拟不限量。

## 停止条件

每个平台的分页循环只能在以下情况结束：

1. 平台明确返回无下一页；
2. 平台返回空结果；
3. 连续页面的稳定标识集合重复，判定平台分页卡住；
4. 用户主动停止；
5. 登录、验证码、连接或平台错误触发可恢复中断。

重复页保护只防止死循环，不作为正常数量上限。

## 数据与恢复

- 继续使用现有逐步落盘方式，已采集数据不等任务结束才保存。
- 保留现有任务 ID、平台隔离目录、检查点和恢复入口。
- 中断后从已有检查点继续；已完成的作品、评论页和账号资料不重复覆盖。
- 多平台队列中，当前平台未正常完成时不自动跳到下一平台。

## 平台范围

- 七个现有平台继续支持其原生的 Search、Detail、Creator 能力，以各平台实际上游实现为准。
- 小红书、抖音、快手继续使用现有公开账号资料补采链路。
- 其他平台保存其原生返回的账号标识和主页字段；不为追求覆盖率伪造公开号，也不在本轮新建额外主页爬虫。

## 校验

- API 与命令行接受 `0` 作为不限量，并拒绝负数。
- 空关键词、空作品 ID、空创作者 ID继续在启动前拦截。
- 每个平台至少验证：
  - `0` 不因本地计数停止；
  - 无下一页或空结果会结束；
  - 重复页面会安全停止；
  -用户停止后不再请求下一页。
- 前端验证三种模式切换、标签输入、单/多平台约束和提交字段。
- 运行现有后端测试、前端检查与构建，并用本地 WebUI 做桌面和移动端检查。

## 边界

- 平台搜索排序、结果窗口、账号隐私、登录状态和风控由平台决定。
- “不限量”会显著增加运行时间、磁盘占用和验证码概率，但程序不再主动按固定数字截断。
- 本轮不增加自动扩展关键词、大模型筛选、并发提速或新的平台接口。
