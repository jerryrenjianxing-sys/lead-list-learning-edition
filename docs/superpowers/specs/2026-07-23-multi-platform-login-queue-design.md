# 多平台登录预热与顺序抓取

## 目标

搜索模式允许选择多个平台。点击开始后分两轮执行：

1. 依次检查所选平台的登录状态；已有登录态则直接通过，未登录则等待扫码。
2. 全部平台登录成功后，按相同顺序使用用户当前配置正式抓取。

## 最小实现

- 保留后端现有的单平台启动接口和单进程限制。
- WebUI 使用现有复选框组件选择多个平台，并在前端维护临时队列。
- API 与命令行增加内部 `login` 爬取类型，不显示在普通“爬取类型”选项中。
- 各平台现有流程本来就是先登录、再按爬取类型分派；`login` 完成登录后自然结束，不修改七个平台核心代码。
- 第一轮全部成功后，WebUI 再逐个平台提交原始搜索配置。

## 状态与终止

- 每次启动保存返回的 `task_id`，通过该任务的状态判断完成，不能根据日志数量判断。
- 当前任务成功结束后才启动下一项。
- 登录或抓取任务非零退出时标记失败，暂停整个队列并显示失败平台。
- 点击“终止”时先取消剩余队列，再终止当前 `task_id`，避免停止后自动启动下一平台。
- 页面刷新会丢失尚未启动的前端队列；当前后端任务仍按原行为继续。为保持最小改动，本次不增加持久化队列。

## 范围

- 多平台仅用于搜索模式；详情模式和创作者模式继续单平台运行，因为不同平台的 ID 格式不同。
- 多平台登录使用二维码方式；不共用一个 Cookie 输入框。
- 平台顺序采用用户勾选顺序。
- 不增加并发、重试、后台队列服务或新依赖。

## 验证

- 队列顺序检查：全部 `login` 任务完成后，才出现第一项正式搜索任务。
- 登录态检查：已有缓存的平台不弹码，缺少登录态的平台等待扫码。
- 失败检查：任一登录任务失败后，不启动正式抓取。
- 终止检查：停止当前任务后，剩余平台不再启动。
- 回归检查：单平台搜索、详情模式和创作者模式保持原行为。
