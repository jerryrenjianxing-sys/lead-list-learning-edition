# 0.5.1 验收记录

本版交付批准的状态、溯源、探测与恢复升级，并修复验收发现的既有桌面与账号恢复问题。原需求及历史测试见 [0.5.0 记录](validation-0.5.0.md)，补充范围见 [本版规格](specs/0.5.1-acceptance-fixes.md)。0.4.3 / 394bc392 仍是唯一正式回退基线。

## 已确认的缺陷与修复

1. v0.5.0 / 780ff22 的 GitHub [发行检查](https://github.com/jerryrenjianxing-sys/lead-list-learning-edition/actions/runs/39584291288) 在后台重启时失败，未发布 Release。旧 HTTP 先关闭而进程稍后退出时，桌面没有启动替代后台，并因 instance 为空而停止监测。外部进程/文件/HTTP 适配器对真实控制器稳定复现；修复后同预算启动且只启动一个替代进程。
2. 独立复审发现停止和正在等待的启动交错，会在停止返回后创建后台。新增生命周期代次和共享启动/停止流程；回归验证取消旧启动和拒绝迟到就绪，不放宽超时或 PID 断言。
3. 真实抖音首次扫码后，原任务续接、1 条内容及 1 条评论成功；正常重开却被判为未登录。离线控制证明：原档案可读 → 执行档案检查后 Cookie 不可见 → 释放 SQLite 连接后可读。原因是连接上下文仅结束事务，不确定关闭句柄，Chromium 无法加载仍被占用的 Cookie 数据库。使用 contextlib.closing 关闭只读连接，保留原失效判断及快照安全规则。

Cookie 回归从受保护 HTTP 提交检查，经真实队列、工作进程和受管理 Chromium 读取合成持久 Cookie；关闭自动循环 GC，旧代码稳定 needs_login，修复后 completed（3.63 秒）。不访问真实平台，不把合成认证视为平台验收。会话/认证组合回归 99 项通过；桌面单元 35 项通过。最终发行重新执行全量检查及包内安装门槛，结果以同版附件为准。

修复后真实抖音档案已在后台和浏览器重开后服务器确认认证有效，无需再次扫码；重开后搜索 1 条及详情/评论各 1 条均完成，计数分别为 1 与 2，达到指定数量。此前网络超时及错误未登录结果仍留在本机历史，不删除失败记录。该检查在独立数据副本上运行，日常数据未被写入；源码实测与最终发行包验收分别记录。

## 发行门槛与限制

发行必须通过本版安装包的正常预算自检、真实 Electron/MD/生命周期、0.4.3 和 0.4.4 双升级、实际卸载重装 0.4.3 回退及 0.5.1→私有 0.5.2。校验公开更新下载后，日常软件空闲时备份完整 schema 4 数据目录再升级，检查原数据与账号文件保留。

本机既有 1.8 秒极短自检清理失败仍如实保留，未放宽断言；正常预算与新增路径的资源清理独立验收。自然风控、1/2/4 小时真实冷却、跨天或重启电脑后的账号保持、其他六平台真实完整采集、干净 Windows，以及真实外部 Agent 收取 MD 附件尚未全部完成。不会故意增加请求触发平台限制，也不宣称七平台永久登录或采集全通过。
