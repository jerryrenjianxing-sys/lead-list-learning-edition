# Desktop startup and reconnect on a large existing workspace

Baseline: ae38cf0c6932e03aaaf53869c29c7473339d1f48 (0.5.4).

The user reports frequent “启动未完成 / The operation was aborted due to timeout”; reconnecting from the tray also fails. The existing authorized backend remains reachable. On the actual workspace, desktop discovery fails after 8.063 seconds because it requires `/api/v1/diagnostics`, whose database `PRAGMA quick_check` takes 12.526 seconds. A separate isolated Electron reproduction confirms that the old shell also remains on its error page after connection recovery.

## Required behavior

- Startup, manual reconnect and periodic readiness must use the existing protected lightweight handshake, without invoking a full database diagnostic. Keep the full diagnostic available as an explicit operation.
- Keep product, version, local origin, authorization and canonical workspace validation. When discovery declares a workspace or instance identifier, it must match the authenticated backend. A public health response is insufficient evidence of authorization.
- After a transient connection failure, a successful periodic check must restore the workspace from the status page. Healthy periodic checks must not reload the current workspace view. A late check must not overwrite a newer reconnect, shutdown or update.
- Preserve existing single-flight startup, owned-process tracking and safe shutdown. Do not spawn duplicate hosts or kill a backend to make reconnect appear successful.
- Apply this as a local repair of the 0.5.4 desktop shell. Keep the installed Python backend, dependencies, schema 6, data and browser implementation. Preserve the paused AI campaign, the three packaging searches, capability counts and 1/2/4-hour and 999 retry rules. Do not publish a release or restart a capability cycle as part of this repair.
- Before local replacement, stop normally and back up the latest business data and original shell. Record old and repaired shell checksums and the source commit; keep the original official manifest as evidence instead of misrepresenting the repair as an official release.

## Acceptance

- A host with a slow diagnostic must still reconnect promptly; unauthorized, mismatched workspace and replaced-instance responses must fail closed. Concurrent reconnects reuse one operation.
- The same actual-workspace discovery loop that failed must pass after repair, with timing recorded.
- Real isolated Electron must reproduce error-page persistence before the fix, then automatically recover after a transient authenticated-readiness failure. Preserve a healthy page route across normal polling and confirm cleanup.
- Run the Electron regression suite and affected packaging/identity checks. Verify the installed repaired shell opens the original workspace and reconnects successfully. Compare original jobs, capability counts, records, analyses and artifacts before and after local replacement.
