# 0.4.4：抖音采集结束判断与错误提示

来源：用户引用「操作」会话，要求定位并修复50个关键词测试中的异常，采用mattpocock-skills开发。用户补充：没有下一页可能确实代表结束，空响应也可能来自风控；两者都应依据响应判断。

## 行为

- 抖音搜索正常返回数据且明确没有下一页，或达到用户设置数量时，正常结束。接口本轮结束不等同于全站采集完整。
- 搜索返回成功业务码、空列表及明确结束标志时，记录 `no_results`，界面显示「无搜索结果」。不能由此宣称平台不存在相关内容或排除风控。
- 缺字段、异常空页、业务错误、重复分页或游标不前进时，停止当前范围，记录原因与脱敏响应摘要；有已保存数据为partial，否则interrupted，不无限翻页或重试。
- 评论及回复同样记录正常结束或异常停止。分页信息不全时，已收到且有效的数据仍保存。
- HTTP错误、空响应、非JSON和明确拒绝请求分别说明，不能仅凭这些响应断言账号被封。原始响应正文、请求头及凭据不写入错误信息。
- 结束记录按任务和运行次数隔离，损坏记录不能冒充成功。恢复沿用原任务、数据集和去重机制，旧轮次的原因不会污染新轮次。
- API v1通过checkpoint.collection补充结束记录，保留旧字段和旧worker兼容。任务列表显示异常原因，详情继续提供日志。
- 不重跑50个任务，不改写历史测试结论、账号或既有数据。旧日志没有响应字段，不能倒推出那47项必然是无结果或风控。
- 其余平台、登录、签名、浏览器管理和自由分析沿用现有行为；不升级依赖，不迁移数据库。本轮不实现增量采集。
