## 状态和保存合同

- 迁移schema4→5，先备份，专用记录轮次、范围、事实、操作与访问等待。事实带任务/attempt、来源层、平台/能力/scope、时间、结构白名单及证据引用。Cookie、token、认证头和完整响应正文不进入公共接口/诊断。
- 平台会话将保存状态、最近认证成功和本次检查分开；来源层区分local_app/browser/platform/storage。空响应、403、超时不足以确认账号风控。
- 范围派发前登记，动态发现后增加；区分计划、已尝试、正常结束、达到数量、无结果、异常、未执行、用户停止。范围完整不等于全站采全。七平台包含实际启用的search/detail/creator/comments/replies/profile；不支持阶段不冒充成功。
- 数据库业务提交是保存成功依据；每轮新增/更新/重复与累计数分开，关联记录修订。原始文件独立记录提交状态，失败可重建，不能声称跨文件事务。
- 停止任何等待/活动任务均关闭自动续接，界面显示明确已停止；仅显式恢复可撤销。旧attempt/generation不能落业务库或覆盖终态，停止与收尾竞态停止优先。
- 每轮历史可分页。清理列表不隐藏仍会自动恢复的任务，应先停止或保留可见等待入口。

## 接口与操作

- 保留APIv1字段与旧入口，在job追加status_detail（lifecycle/wait_reason/result/evidence/counts/next_actions/decision_revision）。
- events支持attempt过滤及结构化事实，保留message；新增job attempts摘要、diagnostics脱敏导出。
- 平台检查/打开/重试保存保留现有返回job id并追加operation_id；操作区分queued/running/completed/failed/cancelled/interrupted，独立GET与取消，复用幂等回执。
- 新增平台probes开始或复用探测、availability查询判断；操作与job都参与同一串行调度/浏览器租约、停止与升级空闲检查。不能凭请求200视为完成。
- 界面和Skill读取同一状态解释。客户端explain/probe/operation；MD入口保持简短，连接不强制自检或探测，个人Skill显式调用策略不变。

## 探测与恢复

- 抖音搜索对照默认“美食”；详情/评论/回复取最近成功公开来源。缺失或失效为未能检查，搜索成功不解除评论等待。探测不生成正式job/dataset/analysis，不保存研究内容。
- 正常空结果不自动探测。异常探测按平台/账号环境/能力合并，同一活动探测只运行一次。未知能力允许原目标预算内首次尝试，不永久阻塞。
- 探测60秒总预算，网络30秒且最多3个实际请求，启动/清理包含在总预算；重试统一预算，不层层相乘。未执行/启动失败/取消/清理失败不同。
- 明确限制或原请求与有效对照均异常，分别记明确/疑似限制；网络、结构不兼容和单内容删除/私密独立处理。未知限制范围保守平台级暂停。
- 初次60分钟，若服务端更久遵循更长时间；失败后再等2小时、4小时，三次自动复查失败转人工。重开/重新认证不清零。
- 只有用户未停止、账号一致、认证有效且对应访问阻塞解除才能重排原任务和原数据集；replay_with_dedup不宣称精确游标续跑。
