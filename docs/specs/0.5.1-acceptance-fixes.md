# 0.5.1：状态恢复版本的验收修复

沿用已批准的 [0.5.0 规格](0.5.0-state-recovery.md)、七平台观测范围及四个对外验收边界。依赖、上游、浏览器和 schema 5 均不再变化；回退固定为 0.4.3 / 394bc392。

v0.5.0 / 780ff22 已创建不可变标签，但发行在真实 Electron 后台重启检查处失败，未发布 Release 或提供更新。保留其标签、CI 和本机验收记录，以 0.5.1 交付同一批准需求及下列修复，不移动旧标签或覆盖旧版本。

- Chromium 档案完整性检查必须在启动浏览器前关闭只读 Cookie 数据库连接，不依赖 Python 循环垃圾回收；不改登录失效、快照撤销或凭据恢复策略。
- Electron 重连等待旧的受管理子进程退出，在同一启动预算内最多创建一个替代进程；失败后继续提供重连。
- 正常退出或更新停止必须撤销已经进行中的启动；迟到的发现结果不能恢复过期就绪状态，不得在停止成功后再创建后台。
- 更新主动停止期间暂停自动监测与托盘启动；更新失败恢复当前程序后可重新连接。
- CI 的隔离桌面失败检查保留合成环境的后台日志，不收集真实用户数据。

验证使用受保护 HTTP、真实隔离 Chromium、Electron 生命周期及安装更新边界。分别记录先失败后通过的 Cookie 恢复、重连及停止竞态；真实账号的少量搜索、评论、扫码续接和重开恢复单独列证据。继续执行双基线升级、实际 0.4.3 回退和私有下一补丁 0.5.2 更新门槛。自然平台限制、长时冷却、跨天、其他平台和干净系统未完成项不能标为通过。
