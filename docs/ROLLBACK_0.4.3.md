# 回退到 0.4.3

0.4.3 是本轮采集改造前的正式回退版本，提交固定为 `394bc39211221a3ee645e75d1eae9110331751f8`。0.4.4 属于改造线，不作为回退目标。0.4.3 仍含此前已有定制，并非纯上游 MediaCrawler。

安装包来自 [v0.4.3 原发行](https://github.com/jerryrenjianxing-sys/lead-list-learning-edition/releases/tag/v0.4.3)，文件名 `MediaWorkbench.Desktop-win-preview-Setup.exe`，SHA256：

```
7a582764a6dba5d4d6aaf1d1cfcc13265ebd86f7a316b77f33ec69663525b50f
```

## 升级前准备

在 0.4.3 或日常使用的 0.4.4 中，停止测试任务并从托盘正常退出。复制完整数据目录到独立备份目录，保留其中的 schema 4 数据库、浏览器档案、加密登录快照、任务与成果文件。可使用升级前最新的 0.4.4 数据，不必恢复到旧日期。

实际路径以设置页的数据目录为准，默认 `%LOCALAPPDATA%\MediaWorkbench\data`。仅备份程序安装目录不能备份业务数据。自动迁移前的 `backups/*.sqlite3` 便于数据库恢复，但不能替代完整数据目录副本。

## 实际回退

1. 停止 0.5.0 的活动任务，从托盘正常退出，确认后台及其浏览器已结束。
2. 将当前完整新版数据另外封存，明确标注“schema 5，包含升级后新增数据”。保留副本并核对大小；后续不删除或覆盖它。
3. 卸载程序，保留数据。用上面的原版安装包安装 0.4.3。该路径不依赖更新器自动降级。
4. 首次正常启动旧版前，把原路径中残留的 schema 5 数据目录改名封存；把升级前完整 schema 4 副本恢复到原数据目录。数据库主文件及 WAL/SHM 属于同一快照，不混用不同备份。
5. 打开 0.4.3，核对任务、记录、分析成果、账号档案和登录保存。平台登录有效期仍由平台决定。

旧版拒绝直接打开 schema 5。不要手改 `user_version`，也不要只用旧数据库覆盖新数据目录中的部分文件。回退撤销此次改造线功能，GitHub 的后续提交与旧发行仍完整保留。

升级后新增数据留在封存的新版目录，需要时用匹配的 0.5.0 程序与隔离目录读取或导出；不能声称旧快照自动包含这部分数据。

## 演练证据

每版 `ELECTRON_UPGRADE_RESULT.json` 分别列出 0.4.3、0.4.4 升级路径及 `rollback_verified`。演练使用独立目录、合成数据和加密合成账号，实际卸载并重装 0.4.3，核对 schema 4 恢复，同时验证新版新增数据仍在单独封存目录。它不替代用户当前账号的真实登录验证。
