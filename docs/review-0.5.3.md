## Spec

审查与真实队列回归共发现8项行为问题，均关闭，独立保留本轴结论：

- P1：等待重试绕过原目标重复异常后的人工处理保护。两种等待状态都保存停止原因，定时释放遵守同一重放限制。
- P2：认证无效仍可定时排队。保存计划但等待认证，并在原生任务卡提供登录或验证入口。
- P2：运行中指定的截止时间丢失。停止收尾后沿用指定时间，不重新抽样。
- P2：账号资料计入100条门槛。仅统计contents/comments/replies，分别提供判定记录量与数据集所有类型合计。
- P2：晚加入的未运行关键词可能被旧任务重试占先。首次执行任务优先，保留登录优先级。
- P2：提前对照成功后，定时释放没有登记一次重放。统一经Availability.resume_waiting执行与记账。
- P1：新增访问恢复路径可能使用旧账号的available结果恢复任务。再次核对当前账号、认证和计划绑定。
- P1：不确定对照结果可能留下无人处理的过期等待。网络、接口及不确定结果保存新随机90–120分钟时间和检查操作。

最终Spec复审：0项待修。最严重的P1账号隔离、重放和永久等待问题均关闭；原任务/数据集、100条边界、用户停止优先、重开保留截止时间及访问保护均符合规格。
