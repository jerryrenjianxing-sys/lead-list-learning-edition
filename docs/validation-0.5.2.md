# 0.5.2 本机重试状态修复

本次按用户最新规则替代此前“正常空搜索直接完成”的默认行为：搜索任务累计去重记录数不超过100条（内容、评论、回复合计）视为未跑通，每次随机等待90–120分钟后继续原任务和原数据集。100是判定阈值，采集数量上限保持用户原设置。请求显式传入`retry_threshold: null`可关闭此规则。

原生`waiting_retry`状态、下一次时间、原因、阈值与随机时长写入数据库，并由同一`status_detail`提供给界面和客户端。`POST /api/v1/jobs/{id}/retry-plan`可配置、暂停到指定时间或停止定时。真正的用户停止会取消计划，后续认证和定时均不能自行启动；手动恢复可重新启用规则。等待中的任务不能清理隐藏。

到期从数据库调度原任务；账号变化及原生平台访问阻塞仍会阻止续接。搜索低于阈值和采集部分失败分别保留原始轮次事实、已保存数据及下一步计划。队列按上次实际启动时间轮转。修复了探测租约调用中`operation`参数重名造成的启动失败。

数据库schema 5→6，迁移前自动备份；回退旧版前必须封存新数据并恢复升级前数据库，不把schema 6交给旧版。

验收记录随本机交付保存：认证HTTP与队列回归验证0/100/101边界、去重、保存重启、到期前不运行、到期原任务续接、用户停止、账号变化、访问阻塞、队列公平性，以及真实渲染任务卡的状态与下一次时间。模拟数据不代表平台限制已经解除；真实采集持续效果须到期后观察。

本补丁仅本机交付，没有将本次研究数据或本机备份上传。
