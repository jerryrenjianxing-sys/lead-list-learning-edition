# 连接与恢复

## 0.5.0 状态与下一步

保留 MD 中的 Python、客户端与 `--instance` 前缀，追加以下命令。普通连接或能力介绍完成后直接继续用户目标。

- `explain JOB_ID`：读取与任务台相同的 `status_detail`，核对本轮新增、更新、重复、累计量、范围确认情况及证据编号。
- `operation ID`：查询原操作的受理、执行、完成或失败；`operation ID --cancel` 取消同一操作。登录、检查与打开平台返回的 `operation_id` 对应实际动作，重复请求复用原流程。
- `probe dy search`：独立使用“美食”作一次搜索对照；评论、回复、详情使用 `comments`、`replies`、`detail`，要求已有最近成功来源。`--no-wait` 受理后立即返回编号。缺少对照显示未能检查，不临时采集研究数据来凑对照。其他平台目前返回未启用。

探测共享串行浏览器与总预算，不写正式数据；搜索通过只证明本次搜索能力。空响应、403、超时及对照失败均不能独自证明账号风控。正常无结果不追加探测。`waiting_access` 的明确限制或疑似限制按保存的冷却等待；网络和接口错误按各自原因处理。重新登录、重启不会清除冷却，三次自动复查仍未恢复时转人工操作。

用户停止任务时调用原任务 `stop`，包括 `needs_login`、`waiting_access`、`waiting_retry`；停止会禁用自动续接。自动恢复须账号一致、认证有效、相关访问阻塞解除。主动恢复沿用原任务及原数据集；更换账号需要用户明确继续。

0.5.2起搜索默认启用低量重试：去重内容、评论及回复合计不超过100条时进入`waiting_retry`，随机等待90–120分钟；账号资料不计入此门槛。`status_detail.retry.record_count`是判定记录量，`counts.dataset_total`仍是数据集所有类型合计，不能混用。下次时间见`next_retry_at`；认证、账号变化或人工复核阻塞时会给出原因和对应操作，而不承诺到期一定启动。显式传`retry_threshold:null`可保留单次搜索行为。定时等待使用`retry-plan`接口，不能用用户`stop`代替。历史终态不自动批量补建计划。

按需分页读取 `/api/v1/jobs/ID/attempts`、`scopes?attempt=N&after=CURSOR`、`events?attempt=N&after=SEQ`。旧版仅有快照时说明历史不完整。`/api/v1/jobs/ID/diagnostics` 下载结构化脱敏诊断，包含范围引用、不含账号、关键词、原文或凭据。SQLite 成功提交表示记录已保存；原始文件失败可在停止任务后调用 `POST /api/v1/jobs/ID/raw-files/rebuild` 重建。

## 接入与旧版本兼容

- `connect`／`check` 找不到实例：启动 Media Deep Researcher 后重试。优先使用当前首页MD文件提供的随包 Python、客户端与 `--instance FILE` 完整命令；默认发现文件为 `%LOCALAPPDATA%/MediaWorkbench/instance.json`。客户端读取其中的本机凭据，文件内容不进入聊天、报告或公开仓库。
- 升级或重开后路径、端口变化：重新复制当前首页MD文件，或由客户端重新发现同一数据目录下的实例。直接使用软件已有的 Skill 与客户端，ZIP 作为备用；不用逐文件重建脚本或另建 Python 环境。本机 Skill 和客户端由安装维护，用户模板、补充资料与研究成果另存在数据目录。
- 授权或兼容检查失败：报告客户端的错误代码、是否可重试及下一步提示。一次健康页有响应不能当作授权成功；401/403 不改走公开接口假装连接。恢复须保持同一数据目录身份，不能对另一份资料库重放请求。
- Electron 桌面提示旧版本后台仍在运行：在旧版托盘选择“退出并保存进度”，等待退出后重开新版。软件内更新在任务和自检空闲时安装；不使用强制结束、删除数据或重复启动后台来解决版本冲突。
- 0.2.0 → 0.3.0 可使用同产品完整安装包升级，也可通过现有软件更新通道。账号、任务和数据沿用原目录；桌面缓存变化不会替换平台的专用浏览器档案。
- 0.3.0 的软件内更新源存在配置错误，检查或下载新版可能失败。已经安装该版时，使用 0.3.1 完整安装包覆盖升级一次，保留账号、任务和数据，随后使用修正的软件内更新。不要删除实例文件或登录档案来修复此问题；API 连接和已有研究任务继续使用原客户端命令。
- Windows 使用MD文件中的原生 `python.exe` 加现成 Python 客户端；PowerShell 脚本只是兼容入口，不要求修改全局执行策略。WSL 中的 Agent 需要通过本机可用的 Windows 工具与正确 Windows 路径调用；纯云端 Agent 无法直接访问用户电脑的 localhost 或本机文件，说明实际限制，不把本地后台开放到公网。
- 请求超时：保留客户端输出的 request_id，执行 `receipt ID`。已登记时使用原响应；未登记时用相同 request_id 和原请求内容重试。改变请求内容必须换编号。
- job interrupted/cancelled/partial/failed：先读 events 和 checkpoint，修复实际原因，再 resume。保存的数据会去重；通用采集恢复会重新经过部分已抓页面，不宣称所有平台都有精确游标续跑。
- 抖音采集结束：有 `checkpoint.collection` 时读取具体停止原因、运行次数和响应摘要。`no_results` 表示平台本轮正常返回空结果；`source_exhausted` 表示接口本轮没有下一页，均不能证明全站采全或排除限制。`issues` 表示存在未确认或失败范围。仅凭completed、空列表或旧日志中的account blocked不能断言采集成功、真实无结果或账号被封；旧版缺少摘要时按日志说明证据局限。尊重用户的重试安排，历史批量测试不自动重跑。
- needs_login：提示用户在“平台登录”完成登录或验证。同账号验证且保存成功后，后台自动继续原任务及原数据集；先查询状态，避免重复创建。账号不一致或无法确认时由用户在页面确认继续，主动停止的任务不会自动续接。
- last_check 为 network_error/unknown：账号和最近成功记录仍保留，不能报告为正常在线，也不要要求重新扫码；网络恢复后重试原任务。session_status 为 failed 表示登录可能有效但保存未完成，软件的“更多操作 → 重试保存”会重新检查并保存。
- 登录信息保存在专用浏览器档案及 Windows 用户加密文件中。不要读取、输出或传送这些凭据；清理任务记录不会清除账号。只有用户明确要移除账号时才使用“忘记此账号”。
- Agent 会话中断：列出 analyses，选择原任务，查看 coverage 和 inputs 的 pending/failed 项后继续。批次编号和写入编号保留，避免重复成果。
- 数据库属于更新版本：运行匹配版本的软件，或在保留现有数据副本后使用之前的备份。客户端不会擅自降级数据库。
